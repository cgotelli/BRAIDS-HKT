# Combined adaptive river worker

The checkout CLI now runs the current combined river bundle from an explicit
input package on either CPU or GPU. It uses augmented f-wave hydraulics with
explicit SSPRK2 and a common timestep for all active leaves. It is not an
implicit solver or a packaged QGIS admission; the CLI rejects this route from
a packaged worker until that delivery milestone is qualified.

## Commands

From the repository root in the configured BRAIDS Python environment:

```powershell
python -m braids_gpu prepare-adaptive-river --profile profile.json --fields initial.npz --output prepared
python -m braids_gpu run-adaptive-river --input prepared --output result --backend gpu
python -m braids_gpu run-adaptive-river --input prepared --output continuation --backend gpu --resume result/checkpoint.npz
```

Use `--backend cpu` explicitly for CPU. No automatic backend choice or fallback
occurs. Output directories must be new. `--until` ends a segment at a specified
physical time; it cannot extend the prepared end time. `--stop-file` names a
cooperative cancellation marker for both preparation and execution. Do not
leave that marker present when starting a new segment.

## Input contract

`profile.json` uses schema `braids.combined_adaptive_river.v1`. The complete
worked regular/cropped examples are generated by
`validation.sediment.river_morphodynamics.adaptive_worker`. The core worker
does not import their geometry or choose their physical parameters.

| Profile field | Meaning |
|---|---|
| `domain`, `assignments`, `grid`, `levels` | Projected-metre polygon, named boundary intervals, base Cartesian grid and nested 2:1 levels |
| `controls` | Explicit `CurrentRiverControls`, including thread count; this combined worker requires MF1 |
| `columns` | Ordered `ColumnMethodsV101` grain identities, sizes and finite layered-bed controls |
| `hydraulics` | Named constant total-discharge inlet and stage outlet definitions; unsupported series/modes are rejected |
| `sediment_boundaries` | Every open boundary, with `kind` of `feed` or `outflow` and ordered per-grain concentration in kg/m3; feed also requires ordered solid-volume flux in m2/s |
| `bank`, `suspension` | Explicit bank-sharing/collapse and split bed/suspended-capacity controls |
| `adaptation`, `adaptive` | `FieldSettings` thresholds/history and an explicit adaptation switch; finest boundary cells are always retained |
| `end_time_s`, `dt_max_s`, `output_interval_s` | Physical clocks; no automatic morphology acceleration |

`initial.npz` contains FP64 arrays in the deterministic **finest hierarchy cell
order** generated from that geometry, not arbitrary raster row order:

| Array | Shape | Units / definition |
|---|---|---|
| `q` | 3 × cells | Water depth, x discharge per width, y discharge per width: m, m2/s, m2/s |
| `rock` | cells | Nonerodible base elevation, m |
| `thickness` | layers × cells | Positive initial layer thickness, m |
| `fractions` | layers × grains × cells | Nonnegative fractions summing to one per layer/cell |
| `concentration` | grains × cells | Nonnegative suspended concentration, kg/m3 |

Dry initial cells cannot carry momentum or suspended concentration. The current
material bundle uses solid/dry densities 2650/1590 kg/m3, fixed-thickness layered
stock and top/base method 1. The supported split-capacity closure, secondary
flow, conservative bank/collapse processes and equilibrium bedform roughness
are composed once; this schema does not provide arbitrary combinations.

Initial layer volumes and water/suspended inventories are area-restricted;
fractions and concentrations are reconstructed from those inventories. Coarse
terrain is the restriction of the prepared finest terrain. The live transfer
retains layer-index alignment. No DEM resampling occurs during a mesh change.

Boundary feed and concentration are intensive quantities. They remain the same
physical prescriptions when boundary faces are mapped, while accumulated flux
ledgers are transferred by overlap length. Changed types/values or assignments
to closed/internal faces are rejected. These are not total-domain sediment
discharges; a future UI must convert requested units explicitly.

## Results and restart

`PROGRESS.json` records loading, mesh preparation, execution and final status.
`frames/INDEX.json` publishes accepted frames with immutable geometry-epoch
identities and hashes. `read_live_frame(output)` returns the latest complete
frame and its geometry; it verifies both before use. There is no fixed-cell-count
assumption and no smoothing in this result contract.

`DIAGNOSTICS.json` records class/water balances, wall integrals, stocks and bank
release. `ADAPTATION.json` records mesh decisions. `checkpoint.npz` includes the
physical owner, mesh, indicator history, coarsening counters and decision clock.
Backend, source/runtime and prepared-input identities are checked on restart.
Old checkpoints are not silently upgraded. A pending mesh change after
cancellation is completed before another hydraulic timestep.

Cache entries become visible only after successful private preparation.
Cancelled attempts remain in `.partial-*` folders with `ABORTED.json` for
diagnosis; they are never read as completed inputs and do not block retry.
Each hit verifies its full manifest. Concurrent writers to the same missing
cache key are not a qualified workflow; use one preparing worker per package.
