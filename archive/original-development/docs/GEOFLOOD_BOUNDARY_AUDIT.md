# GeoFlood boundary source trace — before reuse

Date: 2026-09-06. Scope: the supplied `resources/GeoFlood-master` snapshot, its CPU library callback, representative CPU example overrides, shared CPU/CUDA sources, and hydrograph serialization. **This is a source inspection only: no GeoFlood executable, regression, or boundary experiment was run, and no GeoFlood code was ported into BRAIDS.** The runtime audit in roadmap Step 11 remains open.

Current priority: use this source trace as a reference and finish the existing BRAIDS inlet/filling path. The broader GeoFlood runtime audit below is deferred; it is not a prerequisite for the user-requested reduced G4 milestone.

The source contains useful characteristic-boundary ideas, but its current hydrograph implementation must not be selected as a verified BRAIDS inlet. It has no sampled cross-section stage solver or boundary-ID registry, and several source-level inconsistencies need executable reproductions before any reuse decision.

## Actual callback and data paths

1. **Application initialization precedes example overrides.** The CPU filling-depressions application calls `fc2d_geoclaw_solver_initialize`, then `filling_depressions_link_solvers`, then `fc2d_geoclaw_module_setup`, and finally initializes/runs ForestClaw. See [application initialization](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/examples/cpuflood/benchmark_tests/filling_depressions/filling_depressions.cpp:75).
2. **The library supplies the default callback.** Solver initialization sets `patch_vt->physical_bc = geoclaw_bc2` and `geoclaw_vt->bc2 = FC2D_GEOCLAW_BC2`. The C++ wrapper obtains patch geometry, `q` and `aux`, sets nonphysical faces to `mthbc=-1`, and calls the selected Fortran pointer. The library build explicitly includes `fortran_source/geoflood_bc2_fort.f90`. See [registration](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fc2d_geoclaw.cpp:869), [default pointer](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fc2d_geoclaw.cpp:903), [dispatch](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fc2d_geoclaw.cpp:145), and [build source](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/CMakeLists.txt:32).
3. **Configuration activates a branch.** `GeoFlooddata.write` maps boundary settings into `geoflood.ini` in left/right/bottom/top order; `mthbc=0` selects the custom hydrograph branch, `1` extrapolation, `2` periodic handling, and `3` wall reflection. The default option is `1 1 1 1`. Hydrograph locations separately use left/right/top/bottom order; the writer and the default Fortran lookups explicitly map that order. Do not confuse it with `mthbc` order or the incorrect introductory Fortran comment. See [writer mapping](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/scripts/geoflood.py:169), [default options](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fc2d_geoclaw_options.c:67), [hydrograph locations](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/scripts/geoflood.py:350), and [bottom lookup](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoflood_bc2_fort.f90:228).
4. **The writer creates the data file; the reader does not read `setrun.py`.** `Hydrographdata.write()` writes `hydrograph.data` in the working directory. With `read_data=False`, values come from Python lists; with `True`, Python reads the external hydrograph file and serializes its values into `hydrograph.data`. Total discharge is divided by `channel_width` before writing `hu` in m²/s. Filling-depressions explicitly calls this writer and sets a left custom boundary. See [writer](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/scripts/geoflood.py:332), [list/external branches](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/scripts/geoflood.py:363), [example settings](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/examples/cpuflood/benchmark_tests/filling_depressions/setrun.py:342), and [actual write call](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/examples/cpuflood/benchmark_tests/filling_depressions/setrun.py:611). The example's comment beside `read_data` reverses its meaning; the writer branches are authoritative.
5. **Module setup loads the file once.** C++ calls `FC2D_GEOCLAW_SET_MODULES`, whose Fortran body calls `read_hydrograph_data()`. That reader opens `hydrograph.data`, stores one global channel and hydrograph, and sets its setup guard on successful completion. See [C++ setup](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fc2d_geoclaw.cpp:795), [Fortran setup](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoclaw_set_modules_fort.f90:60), and [reader](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:36).
6. **The active default branch writes ghost states.** It selects cell centres inside a width around `x0` or `y0`, calls `inflow_interpolate`, and uses a dry-state depth expression or the `Riemann_invariants`/`two_shock` routines. Interpolation sets only `q0(2)` for discharge, or `q0(4)` for elevation; it does not compute a cross-section stage. See [default left branch](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoflood_bc2_fort.f90:53), [interpolation](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:155), and [characteristic routines](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:224).

## Findings to reproduce before reuse

These are source observations and predicted failure modes, not measured GeoFlood errors.

| Observation | Consequence / required check |
|---|---|
| The default callback declares `q1(4)` and assigns `q1=q(:,1,j)`, while filling-depressions specifies three equations. See [declaration/assignment](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoflood_bc2_fort.f90:39) and [equation count](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/examples/cpuflood/benchmark_tests/filling_depressions/setrun.py:195). | Nonconforming array assignment for the three-variable SWE case. Compile the active path with array/bounds checks; separate bathymetry from the conservative state. |
| Bottom/top inlet branches assign discharge to `q(2)` and set `q(3)=0`; the right inlet also uses the same discharge sign as the left. See [bottom](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoflood_bc2_fort.f90:240), [top](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoflood_bc2_fort.f90:331), and [right](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoflood_bc2_fort.f90:150). | Verify momentum-component rotation and inward signs on all four sides. Negative discharge also enters a fractional-power depth expression and needs an explicit reverse-flow policy. |
| Both elevation writer branches omit the Froude-number record, but the reader unconditionally reads it before `num_rows`. Elevation interpolation initializes `q0(4)`, while the default boundary then consumes `q0(2)` without initializing it in that path. See [writer](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/scripts/geoflood.py:372), [reader order](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:95), and [interpolation assignment](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:206). | Writer/reader round-trip and initialized-state tests are prerequisites for any stage-boundary reuse. The external discharge writer also duplicates its second input column into the serialized `eta` column; its meaning must be specified before use. |
| The global representation contains one `b,x0,y0`, one set of arrays, and four side flags; `Q/b` is applied using a cell-centre inclusion mask. See [global data](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:19), [Q/b conversion](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/scripts/geoflood.py:370), and [mask](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoflood_bc2_fort.f90:60). | No independent ID-based sections or arbitrary polyline normals. Selected face lengths need not sum to the nominal width. There is no horizontal-stage filling calculation for trapezoidal, circular, or compound sections. |
| For dry interior cells, the callback imposes at least 0.001 m ghost depth even at zero discharge; on wet cells, zero discharge selects wall reflection. The Newton iterations are unbracketed, use hard-coded initial Froude values, and do not return a convergence status. See [dry/zero-flow handling](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fortran_source/geoflood_bc2_fort.f90:62), [invariants](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:236), and [two-shock iteration](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:289). | Test no-inflow dry basins, wet/dry transitions, positivity, reverse flow, and failed roots. The depth floor alone is not evidence of a measured water-volume error. |

A one-row series at exactly its sole timestamp falls through with the initialized zero value. See [reader](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:101) and [interpolation](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/hydrograph/hydrograh_module.f90:189). | Add zero/one-row, repeated-time, malformed-data, and time-endpoint reproductions before adopting the data model. |

## BRAIDS decision and remaining gate

Use GeoFlood as a source of candidate characteristic relations and call-path lessons. Keep BRAIDS's independent sampled-section geometry, stable IDs, explicit normals, and horizontal-stage targets. No GeoFlood boundary routine is approved for direct reuse by this inspection.

The next runtime audit must pin a build and active callback, round-trip every intended input mode, exercise all four sides and wet/dry transitions, then measure **accepted numerical boundary flux and domain-volume balance**. The C++ wrapper explicitly permits boundary callbacks on time-interpolated data that will not update the solution, so counting callback invocations or summing `Q*dt` inside the callback is insufficient: see [time-interpolated callback note](/Users/cmgotelli/Desktop/BRAIDS/resources/GeoFlood-master/src/fc2d_geoclaw/fc2d_geoclaw.cpp:161). No runtime gate is closed by this document.
