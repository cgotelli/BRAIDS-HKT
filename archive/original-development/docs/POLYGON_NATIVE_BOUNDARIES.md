# Native polygon boundary adapter: current scope

[Implementation](../braids_core/boundaries/domain_io.py) · [Native qualification and snapshots](../validation/hydraulics/polygon_boundaries/reports/POLYGON_BOUNDARIES.md)

The first executable adapter supports a rectangular polygon exactly matching a fixed Cartesian grid. The polygon may have any number of collinear perimeter edges. Whole edge selections and edge intervals must end on native face boundaries. Every perimeter face has exactly one owner, including unassigned default walls. The adapter rejects oblique/interior edges, partial native faces, overlaps and stale edge IDs; it never silently substitutes a bounding box or snaps a selection.

`map_domain_faces(domain, assignments, grid, bed_m)` consumes a `PolygonDomain`, its explicit assignments, a `NativeGrid`, and the represented native cell bed array with shape `(nx, ny)`. Coordinates are in the domain's projected metre CRS. `DomainFaceMap` preserves edge/segment/string boundary IDs, side/index keys, lengths, inward normals, midpoints and cell beds. These are sufficient to preview and group the actual openings; the QGIS widget/persistence workflow is still to be implemented.

`write_domain_boundaries(path, mapping, inlets, sections, outlets, ...)` writes `braids_boundary.data` v2 and a JSON geometry/ID sidecar. All active IDs need one matching specification. Numeric IDs derive from sorted string IDs; use the exported `string_to_numeric_id` for suspended and bedload files, rather than assigning separate numeric IDs to each feature.

- Inlet pieces sharing one ID must form a straight contiguous native section. Two collinear polygon edges can form one section and receive **one total Q**. Reuse `InletSpec` and `Section` for the existing normal/critical/depth/stage modes. Section stations increase along native x/y, independently of polygon CCW order; `station_origins_m` explicitly aligns the survey stations. Convex/connected basin and native-bed validation is retained. Disconnected or noncollinear inlet groups require a future explicit allocation/control design.
- `OutletSpec(id, mode='stage', stage_m=..., backflow_policy='error')` applies one absolute stage to one or several selected edges/sides. Each face retains its local outgoing characteristic; no Q is prescribed or duplicated. If both gravity characteristics leave the domain, the local interior state controls the trace instead of the downstream stage.
- `OutletSpec(id, mode='supercritical')` extrapolates outward supercritical states; it rejects wet subcritical states. Stage time series, critical/weir outlet controls and transitions crossing critical flow remain open.
- Outlet reversal defaults to an error. Explicit `allow` requires incoming concentration data, including an explicit zero for clear water. Outgoing suspended flux always uses interior concentration. Wetting a dry stage-outlet cell remains unsupported and is rejected.
- Bedload policies are declared separately using the same numeric IDs and mapped faces. Unlisted faces are bedload walls. Prescribed supply operates only on inward-flowing wet faces; reversed prescribed-supply faces do not automatically become bedload export faces.
- The cut-cell deck accepts `CutBoundary(..., bed_input_kg_s=...)` as one total bedload mass rate for a logical inlet ID. Native version 3 allocates that rate across all currently incoming selected fragments in proportion to their accepted water flux, so splitting one polygon edge into several cut faces does not duplicate supply. The legacy `bed_input_kg_m_s` input remains available for version 1/2 decks.
- Native version 4 accepts `CutSedimentBoundarySeries(times_s, concentration_kg_m3, bed_input_kg_s)` on each inlet ID. Both sediment series are piecewise linear, evaluated at physical SSPRK stage times, and held explicitly at their endpoint outside the listed range. Accepted steps stop at every time-series knot. The bed rate is one total kg/s for the logical ID; concentration multiplies that ID's accepted water influx. The serialized local-reversal policy is currently `reject` only. [Two-inlet native evidence](../validation/sediment/polygon_boundary_timeseries/reports/POLYGON_SEDIMENT_TIME_SERIES.md) includes analytic supply integrals, one-edge/multi-edge explicit outlets, default walls, conservation, morphology, thread equality and restart.
- Native version 15 extends the same contract to `fraction_sediment_series`, keyed by fraction ID. Each fraction may use its own knot times, suspended concentration and total bedload rate. The compact proof integrates `Q(t) C_f(t)` and bedload analytically for each class and checks exact restart plus one/four-thread equality. The [mixed-grain resource event](../validation/sediment/reservoir_multifraction/reports/MULTIFRACTION_RESERVOIR.md) exercises the persisted QGIS project, selected polygon inlet, default walls, active layer and class result ledgers through 600 s.
- Native version 8 adds `CutBoundary(..., bedload_boundary_mode='equilibrium_capacity')` per inlet ID. At each SSPRK stage, every incoming selected face evaluates the active bed-load formula from its boundary-adjacent cell, applies the configured slope correction and admits only the inward component. The conservative accepted ledger records the resulting load. Prescribed total, per-width and time-series modes remain available. [The matched bedload-only control](../validation/sediment/delft3d_intercomparison/bedload_basin/reports/BEDLOAD_BASIN_INTERCOMPARISON.md) matches the independent equilibrium inlet load within 0.474% of the frozen initial reference and the final bed profile within 0.0074 mm maximum.

All exterior `claw.data` boundary codes must be user code 0. Any legacy `hydraulic_bc.data` modes must be zero. `validate_domain_native_deck(work)` checks this before execution, and native v2 also rejects incompatible side codes/overrides. This prevents a forgotten whole-side outlet from opening unassigned polygon walls. A wholly closed domain can use the existing ordinary wall setup; this new open-boundary exporter currently requires at least one selected inlet or outlet.

## Native flux and restart behavior

Format v2 retains the existing inlet row layout and adds outlet modes 5 (stage) and 6 (strict supercritical). Outlet profile/Q placeholder rows are not used to infer a section or impose discharge. The legacy requested-Q/error diagnostic columns are unused for outlet rows; **accepted** fluxes are the water budget authority.

Native v2 explicitly closes unassigned faces in the accepted flux update. It preserves the Riemann solver's normal wall-pressure flux and sets mass, tangential advective and suspended fluxes to zero. This fixes leakage observed with reflected ghost cells alone under the MOL correction at mixed boundaries. V1 inlet/observer behavior is retained.

`braids_flux.data = 3`, together with `braids_exchange_observer.data`, extends the detailed face CSV by two columns: `accepted_sediment_inward_kg_s` and `accepted_sediment_kg`. Modes 1/2 retain their schemas. The values come from accepted numerical fluxes after stage weighting, not requested Q or a reconstructed concentration. Restart checks the extra columns for finiteness and rate × dt consistency while retaining the existing face/step checks. The sidecar's side/index-to-ID mapping groups these records into per-boundary budgets.

For RK steps containing reversal, the weighted scalar flux is not generally the prescribed concentration times the positive part of the weighted water flux: incoming and returning water can have different concentrations. The example verifies the incoming-concentration identity before reversal, prescribed net Q throughout, and independent signed scalar/domain conservation throughout.

## Evidence and remaining work

The 10 s example combines suspended transport, exchange/Exner and bedload. It has two inlets (one split over two collinear edges), an outlet spanning east and north edges, and another outlet. All 80 native checks pass. Water and solids residuals are at most 1.83e-13 m³ and 1.27e-12 kg; absolute default-wall leakage is 2.13e-17 m³ and zero suspended mass. One-patch/one-thread, four-patch/four-thread and restart fields agree exactly; all four accepted ledgers match after restart. Three native executions take about 6.4 s total. This verifies this boundary integration, not steady hydraulic profiles, arbitrary cut cells or experimental sedimentation.

The [cut-cell geometry component and native balance probe](../validation/hydraulics/cut_cells/reports/CUT_CELL_GEOMETRY.md) now represent oblique/partial/internal polygon boundaries without snapping or deleting small cells. `map_cut_cells` in `braids_core/boundaries/cut_cells.py` retains area, centroid, separate disconnected components, shared Cartesian apertures and true polygon fragments with edge/segment/boundary IDs. Its `write_geometry` JSON is an inspection artifact marked `native_timestep_ready=false`; `write_domain_boundaries` explicitly rejects it as a production deck.

The actual resource polygon has 7,061 retained components and 396 partial cells at 20 m. The compiled Fortran/OpenMP balance primitive passes geometric pressure, linear-flux and five-component conservation checks with identical one/four-thread results. These analytically supplied flux probes do not verify hydraulic traces, variable-bed balance, sediment reconstruction or evolving reservoir boundary conditions. The minimum retained area fraction is 0.00010444, exposing a small-cell timestep cost that must be handled explicitly.

An opt-in [native cut-cell executable](../solver/cut_cells/README.md) now integrates these control volumes with WAVE’s unchanged GeoClaw Riemann sources, sediment kernels, area-aware positivity and accepted budgets. `write_cut_case` in `braids_core/boundaries/cut_cell_io.py` takes the geometry plus explicit initial averages, bedrock and `CutBoundary` specifications. It writes a distinct runnable deck, not `braids_boundary.data`. It supports constant total-Q characteristic inlets with dry/supercritical targets, constant-stage outlets and strict supercritical release. Shared inlet pieces must be connected and collinear; outlets may own multiple faces. Reversal is currently rejected.

[Native runs and snapshots](../validation/hydraulics/cut_cells/stepping/reports/NATIVE_CUT_CELL_STEPPING.md) pass variable-bed rest, wet/dry filling, constant settling, Van Rijn exchange/bedload, thread/restart and bounded pulse checks. The 0.125 m pulse has 0.683% relative L1 error and 2.007% peak loss; this does not establish sharp-bed or Zhu accuracy on the new irregular-cell reconstruction. The code retains actual small-cell CFL costs without deleting cells or merging states.

The [slope-corrected resource comparison](../validation/sediment/reservoir_polygon/bed_slope_comparison/BED_SLOPE_RESERVOIR_COMPARISON.md) exercises eight fragments of one polygon inlet ID, default walls and no outlet. Bedload-only and combined-load cases accept their total supplies once, conserve solids, and deposit 4.424 t and 33.189 t in the initial lake by 600 s. Bedload capacity and suspended exchange have separate minimum-depth settings; this prevents the 0.5 m suspended `SedThr` from trapping bedload in shallower wet cells.

The [corrected bounded coupled Zhu window](../validation/sediment/zhu2018_cut_cells/pressure_centered/reports/CUT_CELL_ZHU_CORRECTION.md) passes all 37 frozen gates and 46 compact regression/thread/restart checks. Both unequal strips preserve transverse invariance exactly; front/profile error is reduced but remains measurable. The subsequent [45° steep-bed check](../validation/sediment/zhu2018_oblique/reports/OBLIQUE_BED_VERIFICATION.md) now passes 35 frozen gates in a 300 s window: 7.48% bed-change L1 error overall, 3.50% in triangular partial cells, and 45.03% reduction with refinement. The native multi-ID oblique case now passes (below). The remaining local bed-accuracy issue must be corrected before the resource-DEM event and QGIS selections, previews, persistence, run/restart and results controls. The executable remains separate from the legacy AMR/patch driver; the [delivery checklist](BRAIDS_DELIVERY_CHECKLIST.md) retains the complete scope.

For nonbinary Cartesian spacing, neighboring cell boxes now share the identical indexed plane `(i+1)*dx` / `(j+1)*dy`; using `x+dx` separately could create roundoff gaps and lose a shared GEOS face. The regression verifies all 139 shared faces in a 140-cell strip. This changes grid-box arithmetic and does not snap polygon boundaries or remove small cells.

The [compact native multi-ID oblique fixture](../validation/hydraulics/cut_cells/multi_id/reports/MULTI_ID_OBLIQUE_BOUNDARIES.md) now verifies independent inlet/outlet IDs, selected shared faces, default walls and accepted water/suspended/bedload supplies and exports. A 1 s wet run exercises suspended exchange, Van Rijn bedload and Exner; it is not a reservoir validation. There are 56 actual wall fragments covering four unselected edges (18 m total). No per-face wall ledger exists on this path: independent inventory closure bounds net unaccounted transfer, not absolute per-fragment leakage.

The native per-ID face index preserves ascending face order and exact results; [132 checks pass](../validation/hydraulics/cut_cells/multi_id/boundary_indexed/BOUNDARY_INDEXING.md), including threads/restart and no active IDs. [Finer-bed diagnostics](../validation/sediment/zhu2018_oblique/refinement/reports/REFINEMENT_DIAGNOSIS.md) nevertheless fail to resolve local accuracy, so the actual cut-cell reservoir event remains gated on that correction.

The subsequent [optional reflected-wall WENO correction](../validation/sediment/zhu2018_oblique/wall_weno/qualification/reports/WALL_WENO_VERIFICATION.md) completes the 5 m, 300 s window in 93.08 s with four threads. Overall bed-change L1 is 4.44% and passes 5%; maximum error remains 11.69% and fails 5%. Mode 6 only extends verified 45° half-square walls with complete wet reflected stencils; it is not a general arbitrary-polygon reconstruction. The 61 compact native checks cover conservation, wet/dry behavior, nonzero wall-normal discharge, exchange/bedload, threads and restart. Default mode 5 is unchanged. Python exports and analyzes; all timestep work remains native. Interior face integration, actual resource-polygon accuracy and QGIS integration remain unfinished.
